# 循迹 / Thesis Trail

长期跟踪「可被证伪的判断」，不是收集新闻。每个议题是一页文档，你和 AI 共用它：两边都能改，改动都留痕，可以在原文上划句子评论，对方下次处理时能看到。

到了巡检时间，循迹自己调 DeepSeek API，对每个到期的议题做一次联网研究：搜索、打开网页、核对证伪条件，再把找到的证据、判断和回复写回议题。不需要开 dsh 会话，也不在「自动化任务」里建任务。

## 它记什么

研究请求本身是无状态的：每次都从零开始，不会记得上次查过什么、判断有没有变。循迹把状态放在 SQLite 里，跨请求、跨重启都在：

- **标的（board）**：跟踪的一家公司或一个资产。每个标的有自己的议题和自己的巡检时间。
- **议题（topic）**：一条命题、它的证伪条件、多空两侧的预期和观察指标。
- **证据（evidence）**：带 URL 和抓取时间的外部事实。一条证据可以同时关联多个议题。
- **评估（assessment）**：某个时点对某个议题的判断。`stance` 从 -1（确认偏空）到 +1（确认偏多），只追加不修改，所以能画出判断的走势。
- **巡检记录（run）**：每轮跑过就落一条，哪怕什么都没找到。没有这条，「查过没变化」和「没查过」就分不清。
- **改动与评论（topic_log）**：谁在什么时候改了哪一段、从什么改成什么，以及双方的评论和回复。只追加不修改。
- **研究记录（pass）**：每个议题每次研究一条：用了哪种方式、搜了什么、读了哪些网页、得出什么结论、用了多少 token 和搜索、花了多少钱。

## 第一次打开

新装的循迹没有任何标的。面板上有两个入口：

- **导入议题文件**：别人分享给你的 `.md` 议题文件，或你自己导出的。粘贴内容或选文件，面板会马上检查格式，告诉你有几个议题、全部研究一遍大约多少钱，再选巡检频率，点「导入」。
- **新建标的**：从空白开始，自己写议题。

面板也会告诉你有没有找到 DeepSeek API key（见「研究怎么做」最后一段）。

## 导入和导出

页头点标的名，菜单底部有「新标的」「导入」「导出这个标的」。

导出只包括标的名称、说明，以及进行中和暂停的议题的定义：命题、证伪条件、多头预期、空头担忧、观察指标和重要性。研究记录、证据、判断、评论和费用都不导出。可以复制，也可以下载成 `.md` 文件。

导入会新建一个标的，不会合并到已有的标的。导入的议题全部算作到期，下一次巡检会每个都研究一遍；想马上开始就点「巡检一次」。导入的文字算你写的：AI 想改它们，只能提建议等你决定。

文件格式：

```markdown
# 标的名称（括号里的代码会用作标识，例如 Acme Robotics (ACME)）

说明，可以多行，可省略。

## 议题标题
- 重要性：高
- 命题：……
- 证伪条件：……
- 多头预期：……
- 空头担忧：……
- 观察指标：……
```

每个议题必须有命题和证伪条件，其余字段可省略；重要性只能是高、中、低，不写就是中。一个字段可以写多行，下一行接着写即可。英文字段名（Importance、Thesis、Falsifier、Bull case、Bear case、Metric）也能识别。格式有问题时，面板会逐条列出是哪个议题缺了什么，什么都不会创建。

## 标的与巡检时间

页头「循迹 / <标的名>」：点标的名切换标的，菜单里每个标的显示巡检频率、议题数、待你决定的数量和本月费用。底部的「新标的」新建一个，要填名称、说明和巡检频率。新标的的议题列表是空的，先写议题，巡检才有东西可查。

每个标的的巡检时间单独设置，在页头右侧：

- **每天**：每天在设定的时间巡检一次。
- **每周**：选星期几（至少一天）和时间。
- **暂停**：不再定时巡检。原来的星期和时间会保留，改回「每天」或「每周」就恢复。暂停期间「巡检一次」仍然可以手动跑。

时间按 dsh 所在电脑的时区算（从旧版迁移过来的标的沿用原来定时任务的时区）。dsh 要开着才会巡检：关着的时候错过的巡检，下次打开时补跑一次，错过几次都只补一次。改了时间或从暂停恢复时，如果今天的时间已经过了，等下一次，不会立刻跑。

一个标的同一时间只跑一轮。正在跑的时候点「巡检一次」「立即研究」或「让 AI 处理」，会排在这一轮后面，跑完接着做。

## 研究怎么做

一轮巡检只研究到期的议题，以及你留了改动或评论、AI 还没看到的议题。每个议题一个请求，同时最多两个。按重要性用不同的方式：

- **高 → 深查**：DeepSeek 的深度思考搜索。模型自己多轮搜索、打开网页、在网页里查找，最多约 20 次，要求至少核对三个独立来源，优先财报、电话会纪要、监管文件这类一手资料。一次约 1–2 分钟。
- **中 → 搜索**：一轮普通联网搜索，只记录上次检查以来有实质意义的新事实。十几秒。
- **低 → 速查**：一轮普通搜索，只看有没有重大事件（财报、指引变化、处罚、诉讼、并购、管理层变动、大客户得失），没有就如实说没有，不改判断。

每次研究都要求模型先找反面证据，核对证伪条件；只有证伪条件或它的反面确实成立时，判断才给到 ±1。

写回之前循迹会检查：

- **证据的链接必须是这次搜索结果里出现过、或真的打开过的网页。** 模型自己编的链接直接丢掉，研究记录里会写「丢弃 N 条没打开过的链接」。
- AI 想改你写过的段落，仍然变成建议等你决定；它不能改议题的状态和重要性。
- 回复只能回给这次请求里你留下的那几条评论。
- 研究失败（网络、限流、余额、模型没给出结果）时什么都不写，议题保持到期，你的评论留着等下一轮，底栏显示失败原因。
- 网络、限流、DeepSeek 服务出错、模型没给出结果这类暂时的失败，5 分钟后自动重试，还失败就 20 分钟后再试一次，之后等下一次定时巡检。底栏写着下次重试的时间。key 无效、余额不足这类重试也没用的错误不重试。
- 模型认为证伪条件已经满足时，议题上会出现证伪提醒（见下文）。
- AI 有问题要问你时只会留一条；你回复或解决之前，它不会在同一个议题上再加新问题。
- AI 想改你写过的段落、你还没决定时，它不会每次研究都再提一遍。换了新写法会替换掉旧建议；你回复过的旧建议留在历史里。

需要 DeepSeek API key。循迹按顺序找：插件配置里的 `apiKey`；dsh 模型设置里保存的 DeepSeek key（和 dsh 用的是同一把）；环境变量 `DEEPSEEK_API_KEY`；`~/.dsh/.env` 里的 `DEEPSEEK_API_KEY`。都没有时不发请求，面板顶部会提示怎么设置。

## 用量与费用

点页头的「用量」或底栏的「本月费用」打开用量页：

- **四个数字**：本月费用（其中搜索费多少）、本月 token（和其中缓存命中的比例）、每次研究的平均费用、本月研究次数（搜索和读网页各多少次）。
- **费用柱状图**：按日（30 天）、周（12 周）或月（12 个月）汇总，鼠标移上去看当期费用、次数和 token。
- **按标的**：有多个标的时，列出每个标的的频率、本月次数、token、费用和占比。右上角可以只看一个标的。
- **每次明细**：每个议题每次研究一行：开始时间、标的、议题、方式（深查 / 搜索 / 速查）、用时、未缓存输入、缓存命中、输出、搜索次数、读网页次数、费用、结论。失败的行写着原因。

费用怎么算：

- token 按 DeepSeek 官方价目（元 / 百万 token，2026-11-14 核对）。缓存命中的输入比未命中便宜几十倍，所以单看 token 总量会高估费用。
- 每次搜索查询、每次读网页各按 ¥5 / 千次算。深查一次常搜十几到二十次，搜索费可能比 token 还多。
- DeepSeek 分高峰和低峰价，低峰价是高峰的一半。高峰是北京时间周一到周五 9–12 点、14–18 点。巡检时间设在 9 点以前（默认 08:30）按低峰价算。节假日没有单独处理，按工作日算。
- 数字直接来自每次请求 DeepSeek 返回的计费用量，研究一结束就出现在这里。
- 参考：2026-11-14 实测一个议题，深查约 ¥0.20（token ¥0.085 + 搜索 ¥0.115），普通搜索约 ¥0.05。
- 旧版在 dsh 对话里跑的整轮巡检，方式显示「对话」，当时拿不到搜索次数，没有算搜索费。在普通对话里让 AI 巡检的用量不算在这里。

## 重要性

每个议题有一个重要性：高、中、低。新建时选，之后在详情标题下面的「重要性」下拉里改。已有的议题默认是中。重要性只有你能改，AI 不会改它。

它决定四件事：

- **多久查一次**：高每天查；中每周一次；低每月一次。从上次实际检查的时间算起。你改了或评论了某个议题，它不论重要性都会在下一轮被查。研究里如果发现下一个明确的时间点（比如财报日）早于这个间隔，就按那天查。
- **查多深**：高用深查，中用普通搜索，低用速查（见上文）。
- **列表顺序**：高的排在最前面，标「高」；低的排在最后，标「低」；中不标。
- **侧栏提醒**：高重要性议题的立场翻转在侧栏图标上显示红点；其他议题的翻转只算进数字。证伪提醒不论重要性都亮红点。

改重要性不会让 AI 回复，也不会让议题马上到期，只是按新的间隔重新算下次检查时间。改动记在「历史」里。

## 怎么用议题

议题详情是一页文档，分固定的几段：命题、证伪条件、多头预期、空头担忧、观察指标。右侧是「评论」和「历史」两栏。

- **改原文**：点任意一段，光标落在你点的位置，直接改。点别处就保存，⌘Enter 也保存，Esc 放弃。证伪条件不能为空。如果你改的时候 AI 正好也改了这一段，会让你选用哪个版本。
- **立即研究**：标题下面的「立即研究」按这个议题的重要性马上研究一次，不管它有没有到期。
- **证伪提醒**：AI 研究后认为证伪条件已经满足时，标题下面出现一条红线标出的提醒，写着时间和它的理由；列表里这个议题标「可能已证伪」，侧栏图标亮红点。核对后点「知道了」清掉。把议题改成已结束或暂停、或者改写证伪条件，提醒也会一起消失。之后的研究再认为触发，会更新同一条提醒，不会叠加。
- **研究记录**：页面下方列出这个议题最近 6 次研究：方式、搜了几次、读了几个网页、用时、费用、结论，以及写了什么（新证据、更新立场、回复、修改或建议）。点「看它查了什么」能看到搜索词、读过的网页和模型的完整说明。
- **评论某句话**：在原文里选中一段文字，点「评论」。被评论的文字会一直高亮，点高亮跳到对应评论。不选文字时，在评论栏顶部可以对整个议题留言。
- **让 AI 处理**：写评论时勾选「让 AI 处理」，提交后立即研究这个议题并回复你，不用等定时巡检。不勾选的评论在下次定时巡检时处理。研究中途 dsh 退出了，下次打开 dsh 时会接着处理。
- **讨论串**：AI 的回复挂在你的评论下面，可以接着追问。问题解决了点「解决」，评论移到「已解决」，原文高亮去掉；之后再回复或点「重新打开」会把它放回来。
- **AI 的修改**：
  - AI 改你从没改过的段落：直接生效，段落标题旁标「AI 改于」，在「历史」里可以一键撤销。
  - AI 想改你写过的段落：不会直接覆盖，原文里用删除线和下划线显示它想怎么改，下面有理由和「采纳 / 不采纳」。不采纳时可以写理由，AI 之后不会再提同样的改法。
- **历史**：每次修改都有一条记录，写着谁改的、为什么、改了什么（点「查看改动」看逐字对比）。可以撤销某次 AI 修改，也可以把整个议题恢复到某个版本，或恢复到循迹开始记录之前的最初版本。恢复本身也记成一次修改，所以也能再撤回。
- **段落归属**：每段归最后一次实际改动它的一方。你采纳了 AI 的建议，这段就归你。

侧栏图标上的数字是自上次打开面板以来新增的证据和 AI 改动；红点是高重要性议题的立场翻转或没处理的证伪提醒。面板底栏显示上次巡检的方式和结果（定时巡检时没有到期的议题，就写「没有到期的议题」）、下次巡检时间、「待你决定 N」（等你处理的建议）和「等 AI 查看 N」（你写了、AI 还没读到的改动或评论）；研究进行中显示「AI 正在研究」，上次研究失败时显示原因。

## Agent 工具

定时巡检不用这些工具。它们是给普通对话用的：在 dsh 里和 AI 聊某个标的时，AI 可以读写同一份库，也可以在对话里手动跑一轮巡检。

三个工具。有多个标的时，每次调用都带上 `board`（标的 id）。忘了带时，能从 `run_id`、`topic_id` 推出标的就用推出的；推不出来会返回 `board_required` 和标的列表，不会写错标的。

- `trail_brief`：当前状态的紧凑快照。带 `pass: true` 时，返回结果最前面是手动巡检一轮的步骤（`instructions`）。每个议题带 `due`（是否到期）和 `importance`（重要性）；到期的议题和 inbox 提到的议题给完整内容，其余只给标题、命题和立场。含待回复事项（inbox）、每个议题你改过的段落、待决和被拒的建议。
- `trail_timeline`：某个议题的证据、评估和改动历史。
- `trail_record`：写入。动作有 `run_start` / `evidence` / `assess` / `reply` / `note` / `topic_add` / `topic_update` / `run_close`。`note` 可以用 `field` 和 `quote` 指向具体的一句话。

在对话里手动巡检的顺序：`trail_brief` → 用 `reply` 回复 inbox 里的每一条 → 处理到期议题（`evidence` / `assess` / `topic_update`）→ 有问题要问你就 `note` → `run_close`。对话里的巡检开着时，定时巡检会等它结束（最多 2 小时）。

## 约束

- 新增议题必须给证伪条件（什么情况算这条判断错了）。这是循迹不退化成新闻收集器的前提。
- 证据必须有 `url`。没有来源的内容三个月后无法复核。自动研究的证据还必须是这次真的搜到或打开过的网页。
- Agent 改议题必须写理由。
- 巡检只处理到期的议题，不是每天全部重查。查过的议题按重要性隔 1 天、7 天或 30 天再到期（减 12 小时余量，免得晚几分钟结束的一轮把下一次推后一天）；没查到或研究失败的议题保持到期。你改过或评论过的议题会在下一轮被查。暂停的议题不会到期。

## 存储

默认 `~/.dsh/thesis-trail/trail.db`（WAL 模式）。同时开 desktop 和 web 两个 profile 时共享同一个文件。

长期运行不会让库一直膨胀：每个议题只保留最近 6 次研究的完整说明和查询过程（就是「研究记录」里能展开的那些），更早的只留费用和一句结论；搜索结果本身不存。一直增长的只有用量账目（每次研究一行数字）和你要留的内容（证据、判断、改动和评论）。

删除标的还没有做。不想跟的标的先「暂停」。

从旧版升级时：

- 从「研究板」升级，首次启动会把 `~/.dsh/research-board/board.db` 复制过来，旧文件保留不动。
- 升级时会删掉旧版留下、新版不再用的表和列。
- 从用 dsh 定时任务的版本（v7 及以前）升级，首次启动会把「循迹巡检 · <标的名>」任务的时间、星期、时区和暂停状态抄过来，然后删掉这个任务。删任务时 dsh 会给当初建任务的会话发一条通知，所以升级后第一次退出 dsh 可能会弹「正在运行的任务将会中断」，这时并没有任务在跑。
